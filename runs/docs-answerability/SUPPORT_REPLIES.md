## Reply 2 — answers SUPPORT_REQUESTS.md Request 1 (Claude Code facts for the judge artefacts)

Read 2026-10-10 from the official Claude Code docs: [subagents](https://code.claude.com/docs/en/sub-agents), [model configuration](https://code.claude.com/docs/en/model-config), [hooks reference](https://code.claude.com/docs/en/hooks), [skills and commands](https://code.claude.com/docs/en/slash-commands), and by running our own hook. Each page was read through its first 100,000 characters; the tail (8k to 160k characters) was not read, so a statement that the docs "do not say" something means "not in what was read". Advice only; nothing here is an approval.

**Correction first, and it changes your Q2.** The pilot reports (mine) called the cheapest judge "Haiku 4.5". The harness log for every one of those agents records `claude-haiku-5-5`, so the evidence is for **Haiku 5.5**. Opus and Sonnet were `claude-opus-5-5` and `claude-sonnet-5-5`. The verdicts are unaffected; the label was wrong. The pilot report now carries the correction. Use the logged IDs.

1. **Zero-tool subagent.** The docs do not document a way to give a subagent no tools. `tools` omitted: "Inherits every tool available to subagents if omitted" (so an unrestricted judge also gets `Agent`, Bash and the rest). `tools` with no resolvable entry: the subagent "usually fails to launch with an error naming the entries". `disallowedTools` removes a whole tool even with a specifier. So "no tools" has to be built in layers, and checked: (a) an allowlist or `disallowedTools` that removes everything you can name, including `Agent`; (b) a `PreToolUse` hook with a match-all matcher: the hooks reference says `"*"`, `""` or an omitted matcher "fires on every occurrence", exit code 2 "blocks the tool call" with stderr as the reason, and "exit 2 still blocks even if the hook also prints JSON"; settings-level hooks "also run inside subagents" and the input carries `agent_id` and `agent_type`, so a settings hook can block every tool for the judge's `agent_type` only. A hook in the subagent's own frontmatter runs only while that subagent runs, and project-level frontmatter hooks "run only after you accept the workspace trust dialog" (plugin subagents ignore `hooks`). (c) The pilots' audit after the fact. I have not run a match-all exit-2 hook against a live subagent; the docs' worked example uses a `Bash` matcher. `maxTurns` is a documented frontmatter field; its exact semantics were not in what I read. Treat "zero tools" as unproven until the Architect's tests show a judge subagent whose tool call is refused.
2. **`model: haiku`.** Allowed values per the docs: `sonnet`, `opus`, `haiku`, `fable`, a full model ID such as `claude-opus-5-5`, or `inherit`. On the Anthropic API `haiku` resolves to **Haiku 5.5** today; on other providers it resolves to earlier versions (Microsoft Foundry and Bedrock list Haiku 4.5). The docs say aliases "point to the recommended version for your provider and update over time", and to pin use the full model name or `ANTHROPIC_DEFAULT_HAIKU_MODEL`. Resolution order: the per-invocation `model` parameter, then the frontmatter `model`, then `CLAUDE_CODE_SUBAGENT_MODEL`, then the main conversation's model. Claude Code "doesn't validate" the setting up front, so a wrong ID fails on the first request. **Recommendation:** pin the full ID the pilots logged, `claude-haiku-5-5`, and have the Architect say what happens when the operator's provider cannot serve it.
3. **Nesting and audit.** A subagent can spawn subagents by default, "up to three layers", and the `Agent` tool is withheld only at the depth limit; `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` turns nesting off, and omitting `Agent` from `tools` or adding it to `disallowedTools` stops a given subagent. Each subagent's transcript is `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl`, deleted after `cleanupPeriodDays` (30 days by default), so the scorer must audit inside that window or copy the file. That is the path `execution/usage.mjs` already reads. The pilots audited by parsing each agent's transcript for `tool_use` blocks and failing any that was not a `Read` of its own batch file (plus the hand-back).
4. **Command and skill.** "Custom commands have been merged into skills": `.claude/commands/x.md` and `.claude/skills/x/SKILL.md` both make `/x`. `disable-model-invocation: true` stops Claude from loading it automatically (the user can still type `/x`); the default lets the model invoke it when the description matches; `user-invocable: false` is the opposite (model only, hidden from the menu). `allowed-tools` grants permission-free use and "does not restrict which tools are available". `model` is a frontmatter field on a skill.
5. **`budget-guard.mjs` outside a slice.** Tested, not guessed. With no `runs/` directory: exit 0, no output (allows silently). With a `STATE.md` that has no `Status` line: skipped, exit 0. So an operator running the judge in a repo with no slice is unaffected. The one case that does bite: the guard fires on **every** `Agent` spawn, scans `runs/` and every worktree's `runs/`, and guards the *most constrained* in-progress slice; if any slice there is at or over its budget, a judge spawn gets the same "ask" prompt naming that slice. It asks, it does not block, and it cannot tell a judge from a stage. Not a defect to fix now; the Architect should state it in the contract.

## Reply 4 — answers SUPPORT_REQUESTS.md Request 2 (tool names for the judge's deny list)

Source: the official [Tools reference](https://code.claude.com/docs/en/tools-reference) (table read on 2026-10-10; the page says "The tool names are the exact strings you use in permission rules, subagent tool lists, and hook matchers"). Advice only; nothing here is an approval.

**1. The built-in tool names in that table (46):** `Agent`, `Artifact`, `AskUserQuestion`, `Bash`, `CronCreate`, `CronDelete`, `CronList`, `Edit`, `EndConversation`, `EnterPlanMode`, `EnterWorktree`, `ExitPlanMode`, `ExitWorktree`, `Glob`, `Grep`, `ListAgents`, `ListMcpResourcesTool`, `LSP`, `Monitor`, `NotebookEdit`, `PowerShell`, `PushNotification`, `Read`, `ReadMcpResourceTool`, `RemoteTrigger`, `ReportFindings`, `ScheduleWakeup`, `SendFeedback`, `SendMessage`, `SendUserFile`, `ShareOnboardingGuide`, `Skill`, `SubagentHandback`, `TaskCreate`, `TaskGet`, `TaskList`, `TaskOutput`, `TaskStop`, `TaskUpdate`, `TodoWrite`, `ToolSearch`, `WaitForMcpServers`, `WebFetch`, `WebSearch`, `Workflow`, `Write`. (`Task` is the old name of `Agent`; the subagents page says existing `Task(...)` references still work as aliases, so a deny list should carry both.)

**2. Why a deny list cannot be the wall.** The same page says some tools are registered only when conditions hold ("the tool is never registered there"): by Claude Code version, by provider (not available on Bedrock, Claude Platform on AWS, Google Cloud's Agent Platform or Microsoft Foundry), by model, and by surface. So the list differs by version and platform, and a list written today misses any tool a later version adds, which a subagent with `tools` omitted would inherit. A deny list is a snapshot of what exists now. **The control that survives a new tool is the default-deny one: the match-all `PreToolUse` hook (exit 2) that refuses every call, and a test that shows a call being refused**, which is exactly what record 5 amendment 2 asks for. Keep the deny list as a second layer and a readable statement of intent, not as the thing the zero-tool claim rests on.

**3. MCP wildcard.** The tools reference page does not mention `mcp__*` or any wildcard for subagent `tools` or `disallowedTools` (I searched the page text and found no match). The hooks reference does say that a *hook matcher* containing other characters is a regular expression, for example `mcp__memory__.*`, and that a bare server name such as `mcp__memory` "matches nothing". So for MCP the supported control is the match-all hook, not a name in a list. I did not verify any wildcard form in `disallowedTools`; do not rely on one.

**4. `disable-model-invocation` on `.claude/commands/` files: not confirmed.** The [skills and commands page](https://code.claude.com/docs/en/slash-commands) says `.claude/commands/x.md` and `.claude/skills/x/SKILL.md` "both create `/x` and work the same way", and lists "frontmatter to control whether you or Claude invokes them" among the things *skills add*. It documents `disable-model-invocation: true` on skills (example: a `deploy` skill) and does not say a command file honours it. I did not find a sentence that settles it. **Safest reading:** the documented place for that flag is a skill, `.claude/skills/aveto-judge/SKILL.md`, which still gives the operator `/aveto-judge`. If the Architect moves the artefact from a command file to a skill, that changes the path of an artefact the owner approved under rule 5 (record 5 names "the command `/aveto-judge`"); the behaviour approved (runs only when the operator types it) is the same, but the owner should be told rather than discover it. Whether to ask is the Orchestrator's call.
