## Deviations from the spec, and why

1. **`JudgeCall.attempts: int = 1` and `JudgeTransportError(category, attempts=1)`; `JudgeNotConfiguredError`.** The spec says the adapter retries by itself, yet section 3 says the pipeline reserves before attempt 2. With the specified port the pipeline cannot know. So the pipeline reserves one `R` at admission and charges `(attempts - 1) x R` **after** the fact. Consequence: the cap can be overshot by at most one `R` per extra attempt (about $0.02 to $0.05), and the next admission is refused. Reserving `2R` at admission would remove that at the cost of pausing earlier. Owner / Security may prefer that; it is a one-line change in `pipeline._ask`. Both new fields default, so the AI Engineer's code compiles with or without them, but **the adapter should set `attempts=2` when it retried** (success or failure). `PlaceholderJudgeClient` raises `JudgeNotConfiguredError(RuntimeError)` (the spec's message); the pipeline maps it to `judge_error` and releases the reservation (nothing was called), so a build with no key does not burn the day's budget.
2. `AskService.ask(raw, client_ip)`: `client_ip` is the already-resolved address (`limits.resolve_client_ip` in `app.py`), not raw headers; hashing happens inside the service. Kill switch, body-cap and shape refusals go through `AskService.refuse(outcome, client_ip)` so each still writes its one abuse line.
3. `create_app` gained keyword-only `clock` and `monotonic` (tests only; production uses the real clocks). `app.state.service` exposes the service.
4. `HtmlRenderer.page(state)`: I fixed `state` as `Outcome | None` (None = empty page, `Outcome.SERVICE_OFF` when the kill switch is on). The spec left its type open.
5. `AskResult.admitted` (true for answer / no_confident_match / judge_error) is the Frontend's rule for "store and 303" versus "render with the text back".
6. A `judge_error` from a failure in step 6 (`PayloadMarkerError` or any retrieval error) is `admitted` too (the spec's list), though no model was called; it consumes no allowance (steps before 7 do not).
7. `ruff` in this repo flags blind `except Exception`; the fail-closed catches carry `# noqa: BLE001` with the reason.
8. Spend note: `judged_today` counts model calls that settled (including failed ones that kept their reservation) but not the no-adapter case.

## Review round 1 (CR-1, CR-2, CR-5, CR-6)

Source touched: `aveto_service/limits.py`, `pipeline.py`, `app.py` only.

- **CR-1.** `SpendCounter.reserve` closes the day only when SETTLED `spent + amount > cap`. When only in-flight reservations leave no room (`spent + in_flight + amount > cap`, `spent + amount <= cap`) it returns None for that request (paused) and the day stays open. No model call is made when a request does not fit. `peek` is unchanged: the floor check may refuse a request without closing. **Tech spec §3 step 7 ("and close the day") is superseded by CR-1.**
- **CR-2.** `_judged` charges a failed call by `JudgeTransportError.category`: `status_4xx` and `connection` charge 0 (never billed); a transport error with `attempts == 0` (`prompt_hash`, nothing sent) charges 0; `timeout`, `status_5xx`, `stop_reason`, `tool_use`, `other` and any non-transport exception keep the full reservation per attempt. A success still charges actual cost. The call is still counted as judged.
- **CR-5.** Under the admission lock, immediately before `reserve`/`record`, `day` and the monotonic time are taken again, so a midnight straddle during retrieval reserves on the new day.
- **CR-6.** `StarletteHTTPException` handler (404, 405, and any other) returns the same `{"detail": ...}` JSON with `Cache-Control: no-store` and `X-Content-Type-Options: nosniff` (keeping `Allow` on 405).
